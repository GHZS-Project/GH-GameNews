# 运行与修改规则

## 范围

- 公开版保留：资讯采集、清洗、今日资讯阅读、抓取资讯、日报/周报海报、飞书同步和机器人推送。
- 公开版不包含：人工简讯编辑器、编辑草稿历史、拖拽编辑和对应前端/API。
- 定时流水线仍会在内部生成简讯数据供海报与归档使用，但不会展示编辑界面。

## 允许直接修改

- `src/` 中的只读资讯页面、抓取资讯页面、导航和样式。
- `server/crawler/` 中的过滤、解析、限流、去重和图片处理。
- 回归脚本、测试和文档。
- 对已有接口的小范围修复，保持现有响应结构。

## 修改前确认

- 修改 `server/database.js` 的表结构或字段语义。
- 批量清理、覆盖或删除数据库、抓取缓存、图片、海报归档和日志。
- 新增依赖或改变发布包体积。
- 调整定时任务时间、采集范围或 Firecrawl 额度。
- 修改飞书 Base、机器人目标群或生产凭据。

## 禁止

- 把 App Secret、群 ID、Base Token 或真实 `.env.local` 提交到仓库。
- 把数据库、缓存、日志、备份和 `node_modules` 纳入 Git。
- 恢复人工简讯编辑页面或开放编辑草稿 API。
- 用前端假数据绕过采集失败。
- 对未配置或未授权的站点扩展扫描。
- 在未备份的情况下批量清理生产数据。

## 前端

1. Hash 路由只保留 `#/dash`、`#/feed`、`#/crawler`。
2. API 请求集中在 `src/services/api.js`。
3. 主题使用 `data-theme` 与 CSS 变量。
4. 保留加载、空数据、失败、禁用和恢复状态。
5. 桌面和 390px 移动端都要检查文字、按钮和卡片不溢出。

## 后端

1. API 成功响应保留 `{ ok: true, ... }`，失败使用 `{ ok: false, message }`。
2. 单来源、单文章或单图片失败应隔离，不阻断其他项目。
3. 文章 ID 必须由来源和 URL 稳定生成，不能使用随机 ID 作为去重键。
4. 所有外部请求设置超时；Firecrawl 设置并发、去重和额度边界。
5. 新增环境变量必须同步 `.env.example`、README 和部署文档。
6. 服务端启动后检查 `http://127.0.0.1:64424/api/health`。

## 爬虫与清洗

1. 候选阶段只保存标题、游戏名、来源、分类、详情 URL 和初始分数等基础字段。
2. 列表过滤负责排除无关内容，评分只负责排序，两者不能混用。
3. 论坛水帖、排行榜噪声、抽奖、礼包、兑换码、广告和下载导流优先排除。
4. 正文需要经过长度、广告词、游戏匹配和事件信号判断。
5. 过滤器变更至少增加一个正样本和一个负样本到 `scripts/crawler-regression.mjs`。
6. 真实站点抓取先做小样本验证，再执行批量任务。

## 数据保留

- 活跃文章按最近 48 小时窗口处理。
- 日报、周报和精简快照按现有保留策略独立保存。
- `published-posters/` 是公开静态归档；运行时海报在 `output/`，不进版本库。
- 清理操作必须打印目标、时间范围、影响数量和备份位置。

## 验证顺序

```text
node --check server/index.js
-> npm run build
-> npm run check:crawler
-> npm run check:poster
-> 启动服务
-> /api/health
-> 桌面和 390px 浏览器检查
```
